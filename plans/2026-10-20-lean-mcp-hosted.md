This supersedes the local-only restriction in `2026-10-20-lean-mcp-prototype.md` for this one controlled trial. Keep the normal build/default handler baseline. No dependencies, resources, routes, billing upgrades or permanent authentication changes.

1. Record the existing Worker version and 100% deployment before touching it; retain an exact-version rollback command. Extend only the consented diagnostic helper for pinned legacy/modern clients and sanitized start/end times, lane and phase labels. All credentials stay in memory and are revoked on exit. 2. Use the existing auth Worker/account/KV. After checked source merges, deploy its baseline build first so both candidates use the same source revision and data. Record this reference version and verify source health, legacy/modern discovery and current authorization checks. Retain the original version as emergency fallback. No secrets are read, replaced or logged; cf deployment preserves existing credentials.
3. In each phase (baseline then lean), each pinned protocol lane runs five calls of each fixed read: guide, Darren Moore profile, caretaker statistics, 1942/43 wartime matches and the Songs page. After a 90-second pause shared by both lanes, run two more calls of each per lane. This bounds primary reads to 140 total. Discovery and a few security/signature checks are recorded separately; no edit, draft or publication operation is invoked. Keep unknown/failed/missing telemetry, never interpret missing CPU as zero. Correlate POST /mcp invocations within each receipt's request interval and expected deployed version, refusing ambiguous matches.
4. Arm a separate bounded rollback watchdog before activating lean. It restores the recorded baseline version starting after at most 15 minutes (or on the explicit finish signal), and verifies source health and the actual active 100% version. CLI calls have timeouts and bounded logs. If baseline/lean deployment, semantic checks or telemetry collection fails, restore baseline immediately, using the original fallback if necessary. Do not leave an inconclusive candidate active while waiting for owner input.
5. Predefined retention threshold: all correctness/security checks and every read must succeed; at least 85% of primary call CPU readings must be available in each candidate and at least 20 readings per lane; lean p95 must improve by at least 20%, its share above 10 ms must not increase, and its paused/heavy Songs reads must all have available CPU readings at or below 10 ms. These are conservative exploratory criteria, not proof of all future requests. If any criterion fails or measurements are inconclusive, restore baseline. Keep the normal source default baseline even if the trial is promising; a permanent promotion needs its own checked change after reporting measurements.
6. Preserve sanitized receipts, matched telemetry, version IDs and the decision in `plans/evidence/2026-10-20-lean-mcp-hosted.json`.
