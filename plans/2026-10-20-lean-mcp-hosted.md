## Completed comparison and rollback

PR #39 passed all 70 tests, both compiled protocol lanes, required validation and its exact served preview before merging as `425d60bba3da33423d41b559690535e9b05124b7`. The reference deployment is version `395fa292-bdd8-48c1-832e-271696fae0a3`; the bounded lean version is `b67b0d6d-5ff1-4d9c-b0da-ee344425f0b8`. Both used the same source revision and published archive data. Actual unknown-tool signature checks distinguished the two implementations in both protocol families. All fourteen tools remained discoverable.

All 70 baseline reads and 70 matching lean reads succeeded. Matched CPU telemetry covered 62 baseline calls and 56 lean calls; missing readings remain unknown. Baseline median/p95/maximum were 11/22/29 ms; lean 7/19/36 ms. The measured share above 10 ms fell from 33/62 to 16/56, but lean's p95 improvement was only 13.6%, below the predeclared 20% threshold. Its available timings covered 80%, below the 85% requirement. Paused/heavy readings remained above 10 ms and incomplete: lean's paused legacy guide reached 36 ms and a modern Songs-page read reached 23 ms. This supports lower typical overhead, not dependable Free-plan headroom or an explanation for the remaining spike. The sequential runs and missing telemetry limit causal conclusions; no additional candidate was attempted.

The watchdog armed at `2026-10-20T13:27:53.215Z` and, on the explicit finish signal, confirmed restoration at `2026-10-20T13:31:50.331Z`, well inside its 15-minute bound. It positively checked the active 100% deployment and baseline source health. No fallback or bypass was needed. Ten further fixed reads across both lanes succeeded after rollback; both signatures confirmed the reference handler, and the sourced Darren Moore caretaker query still returned six matches, three wins, two draws and one loss with retained evidence. The lean and restored semantic summaries agree. The client revoked its credential and exited; the watchdog exited normally.

The decision is **rollback / do not promote lean**. Default source and the live auth Worker are baseline. The existing Free account subscriptions read returned `[]`; no paid plan, billing setting, storage resource, public route, content edit, draft or publication was introduced by the trial. The public deployment contains the checked engineering changes with its default baseline selector; the auth deployment remains the checked reference version, independently of later documentation-only publication revisions. Existing npm tooling reported an available major update (11.19.1 to 12.2.0); it was not upgraded as part of this CPU investigation.

Sanitized receipts, available invocation timings, failed retention criteria, semantic checks and the positive rollback receipt are in `plans/evidence/2026-10-20-lean-mcp-hosted.json`. No raw headers, tokens, request bodies, version environment values or owner-account details are retained there. The checked evidence records all 150 planned comparison/restoration reads and the absence of tool errors; the earlier locally rejected legacy pin was a helper setup error, outside those reads. CPU reliability remains unresolved. Before another production change, the next narrower investigation should capture the paused guide's transport/runtime work; removing repeated tool registration did not remove that spike.
