# Research-aware museum connector

Status: user approved the foundation and three-profile trial on 20 October 2026, including read-only archive tools, sourced manager/tenure records and CPU optimisation. Preserve existing archives; no paid services or new dependencies.

## Outcome

Claude can answer bounded match-history questions from the museum's actual records, explain coverage and evidence, and prepare sourced manager profiles with reproducible performance figures. The same records and calculations must serve the public website and connector. Research uses available web tools; the connector does not invent biographies, supply its own paid AI, or claim to browse when no browser/search tool is available.

- Authenticated MCP requests previously measured 14–23 ms CPU with outcome ok, exceeding the nominal 10 ms Free budget. Diagnose and reduce this before expanding runtime work. A passing request using overrun flexibility is not proof of Free reliability.

## Design boundaries

Retain canonical match files, source references, IDs and all current public routes. Add versioned, derived, bounded lookup artefacts at build time instead of parsing and returning the entire archive for every question. Derived IDs include ledger identity without altering original IDs. Returned pages and statistics include the source revision, checked timestamp, filters, evidence breakdown and coverage limitations. Reject unknown filters rather than silently broaden a query. No silent truncation and no cross-ledger grand total by default.

Add a separately sourced manager/person and tenure register only after design approval. Distinguish a person from each spell, caretaker from permanent appointments, and early secretary/selection arrangements from modern managerial authority. Appointment dates alone do not prove which match was their first or last: permit sourced match boundaries and explicit attribution exceptions, report unresolved matches, and never fill disputed boundaries by guesswork. Unknown manager attribution must remain visible.

Use existing result semantics: score after extra time determines match W/D/L; penalties determine progression separately. Statistics explicitly state scope, counted matches and denominator. League positions, honours and biographical claims require separate documentary sources; do not infer them from fixture scores. New evidence labels apply to new records without making older archive rows unsaveable or silently upgrading their evidence.

Research support should return a task checklist, sources and existing related material, then validated drafts through the current preview/approval/publication flow. First trial: three sourced manager profiles covering an ordinary tenure, a caretaker/permanent transition and repeat spells; select the people after checking source coverage. Expand the register and profiles in verified increments, not a generated claim of complete coverage.

## Acceptance examples

- "How did Albion perform against Villa under this manager?" returns actual counted records, explicit competition/tenure/evidence scope and links to sources, not guessed numbers.
- "Compare the two spells" keeps the person's separate appointments visible and avoids combining caretaker and permanent roles silently.
- A wartime request returns a separate ledger and carries single-source/discrepancy notes; an official competitive request excludes wartime and annulled games.
- A request reaching beyond recorded history reports the missing interval; 1878 club formation does not turn an 1883-starting results dataset into a complete all-time ledger.
- "Research this manager and draft a profile" distinguishes web evidence, existing museum facts, reproducible match statistics and unanswered questions, then uses the existing checked preview and approval process.

## CPU work — initial measured change

The installed SDK already preloads its wire schemas in the workerd shim; the compiled unminified bundle confirms the call survives bundling. Do not add redundant protocol preloading. Node inspector sampling of the current handler and repeated SDK protocol traffic shows schema JSON conversion, schema parsing, server registration and allocation/GC work. Tool schemas were newly allocated for every fresh server, and discovery reconverted their JSON descriptions. Cache only those static definitions and Standard Schema input/output descriptions at module evaluation; delegate validation to the original Zod schema on every invocation. Keep fresh servers, handlers and per-call GitHub access checks.

In a 200-iteration Node 24 jitless protocol comparison (construct, connect, list tools, guide, close), median CPU dropped from 1.079 ms to 0.489 ms. First iteration dropped from 21.728 ms to 15.275 ms; this is local evidence, not proof of hosted Free compliance. A new actual SDK test checks identical discovery, retained defaults, invalid input rejection and concurrent user separation. 42 tests and the compiled build passed.

Production CPU capture against the verified active auth version 7de64d8b-8ab8-4b91-bfe0-b75baa7f792b returned [10393] No recent executions were found for this Worker, even around live read-only Claude calls. One attempt also encountered expired cf sign-in, which the owner renewed. Do not interpret these empty/unavailable captures as a clean CPU profile. A temporary isolated Miniflare profiling harness failed configuration/startup twice and was abandoned; the existing compiled project runtime checks continue to pass. Hosted before/after telemetry remains the acceptance gate.
