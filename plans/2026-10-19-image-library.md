# Credited image uploads and reusable library

The user approves the proposed free upload → add credits → reuse workflow, including thumbnails, automatic dimensions and size checks. Extend the existing Decap/GitHub draft workflow and Astro static assets; no new dependency, service, paid storage or new authentication component. Existing seven photographs, their identifiers and public URLs remain compatible. The original museum and match archives stay untouched.

1. `src/lib/image-paths.mjs` and `src/lib/image-files.mjs`: resolve legacy asset names and bounded `/uploads/` paths; read actual format, dimensions and byte size using Astro's existing metadata utility; validate upload limits and reject malformed, traversal, symlink, unsupported or uncredited image records. Keep existing image records saveable. Verify real raster fixtures and negative controls; compare old emitted pages.
2. `src/lib/editor-schema.mjs`, `public/admin/image-widget.mjs`, `public/admin/preview.mjs`, `scripts/prepare.mjs`: enable creation in Photographs and credits, use the existing native image picker with thumbnail and automatic dimensions, keep caption/alt/author/licence/source fields, show credited image preview and gallery listing. New uploads are attached while editing the photograph draft. Raw Media uploads outside a draft must not bypass protected publication. Reuse published photograph relations on pages, exhibits and eras; preserve existing fields.
3. `scripts/check-editorial-diff.mjs` and build verification: allow only raster uploads in the controlled folder alongside editorial JSON, require asset references and reject replacements/deletions of published uploads or unrelated code/data. Files and metadata go through the same preview/check/publish path. Do not weaken main protection. Add tests for stale/missing image data, invalid file types/size, unsafe paths, unreferenced files, dimensions and editor config.
4. Add a public image-library page with thumbnails/credits and stable per-image preview routes; update README and publishing help with exact steps, free limits, draft caveats and reuse/recovery. Do not claim new hero-image editing if those templates retain their original photo.
5. Run tests/build, original content/archive comparisons, browser upload/select/thumbnail/preview/reuse checks in a disposable local backend, then ship checked PR and verify actual deployed image/gallery/editor output. Test signed-in publication only when the owner browser is available; preserve existing unsaved Safari drafts. Record exact evidence and any remaining human acceptance step. Commit/push completed work and clean task servers, caches and generated output.
