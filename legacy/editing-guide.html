Before your first visit

Create your own free GitHub account and give your username to Steve. Once you’ve accepted his invitation to help edit the museum, choose Login with GitHub in the editor. You don’t need a Cloudflare account, a domain or a paid plan to edit and publish.

The public museum is at throstle-and-stripes.steve-e85.workers.dev. Save the editor and this guide as bookmarks.

Your first edit

  1. Choose a page. Open Pages and choose, for example, Songs & terrace culture. Find the block containing the words you want to change. Start with one small edit.
  2. Save a draft. The preview beside the form helps you see changes as you work. Some blocks update immediately; others need the full saved preview to show their behaviour. Saving doesn’t change the public museum.
  3. Open View preview. Give the checks a few minutes to finish. Read the whole page, try its links and check it on your phone. After saving again, reload the saved entry when checks finish: an old preview link can linger. Make sure your latest wording appears.
  4. Mark it Ready, then Publish now. Only publish the version you’ve checked. If checks fail, fix the draft and save again; the previous public version stays in place.
  5. Check the public page. Publishing takes another build. Use the status below, then visit the museum and check your change. A draft preview is a separate address, so it doesn’t prove publication has finished.

New pages, familiar building blocks

In Pages, choose New. Give the page a title and a short address such as my-albion-memories. Use lower-case words with hyphens and keep the address once it’s published, so bookmarks keep working.

Start with one Page introduction. Add content blocks for text, photographs, facts or other supported content, and drag them into order. A Section groups blocks into one, two or three columns, with choices for background and spacing. Preview a narrow screen too: columns stack on phones.

To reuse a layout, open Page templates, create a named template and copy an existing page or template using the Content blocks controls. Save, preview and publish the template. You can then apply it to another page. Each copy is independent: changing a template later won’t change pages already made from it.

Put it in a collection

Choose a published Museum collection in the page form to group related stories. You can create a collection first, preview and publish it, then select it on your page. Pages & collections helps you check where your page appears.

Keep history and sources together

Add source links beside the claims they support. Keep labels such as “single-source” or “unverified” where evidence is incomplete. A Manager performance block calculates figures from the archive when you choose a researched manager; those numbers aren’t editable text.

Add a photograph, with its story

  1. Open Photographs and credits → New and upload through the Image field. Use JPEG, PNG or WebP, up to 5 MB. Give replacement files a new filename.
  2. Describe what the photograph shows for someone who cannot see it. Add the credit, source and permission or licence details. Use photographs you have permission to publish.
  3. Save, preview and publish the photograph record. Then refresh the editor and choose it in your page’s Photograph block, exhibit or era.

Browse the image library before uploading: the same photograph can be reused. Editing a shared photograph record updates its uses; check its credits carefully.

Prefer to talk it through?

The optional Albion museum connector lets Claude read the museum, research the match archive and prepare drafts. Steve can help connect it using your GitHub login. The connector address stays the same when the museum moves.

Try: “Draft a page about my first visit to The Hawthorns, using the museum’s blocks. Keep my memories separate from researched facts. Show me the checked preview before publishing.”

Read the preview yourself, check the sources, and ask Claude to publish that exact version only when you’re happy. Claude’s drafts are separate from the editor’s draft list. Connector setup and help.

If something doesn’t look right

The preview still shows old words
Wait for checks to finish, reload the saved editor entry and reopen View preview. Check your latest wording before publishing.
A check fails, or Publish isn’t available
Keep your draft. Look for a field that needs completing and try saving again. If it still fails, send Steve the page title and the message shown. Don’t share passwords or sign-in codes.
You’ve published a mistake
Edit the wording back, save a draft, preview and publish again. GitHub keeps earlier versions; Steve can help recover content if you need it.
You want to change match results or add a new kind of block
Ask Steve. The archive and calculated totals are protected from ordinary page edits, and new block types need development. Existing blocks, pages, layouts and collections are yours to arrange.
